Known Limitations

  • No ground truth: Without manually annotated relevance judgments, Recall@K metrics are estimated, not measured with traditional IR methodology
  • Domain metadata UNKNOWN: All chunks have domain='UNKNOWN'; domain filtering reliability depends on query understanding accuracy (rule-based extraction handles common patterns well)
  • PostgreSQL full-text search: Single language (English); no legal terminology specialization; performance tuning may be possible with custom dictionaries
  • Multilingual support: Primarily English corpus; Hindi/Tamil/other Indian languages have limited support (would require language-specific embeddings and lexical indexing)
  • Reranking lightweight: No LLM-based reranking (cross-encoder); uses lexical boosting and domain scoring which provide 2-3% improvement but no semantic reranking
  • Corpus sparsity: Some domains (ABS, specific rules) have limited content; expansion may improve coverage

Architecture: Complete Retrieval Pipeline

QUERY (e.g., "Section 3(d) of Patents Act")
  ↓
QUERY UNDERSTANDING (Phase 2)
  ├─ Language: en
  ├─ Intent: PATENT (0.95)
  ├─ Domain: IP (0.95)
  ├─ Legal refs: {Patents Act 1970}
  ├─ Regulation refs: {section_3(d)}
  └─ is_exact_match: true
  ↓
LEGAL TERM EXTRACTION (Phase 3)
  └─ Extract: "Section", "3(d)", "Patents Act"
  ↓
PARALLEL RETRIEVAL (Phases 0, 4)
  ├─ VECTOR SEARCH
  │  └─ Query embedding → pgvector IVFFLAT → top 20 (45ms)
  │
  └─ LEXICAL SEARCH
     └─ PostgreSQL ts_query → top 20 (22ms)
  ↓
HYBRID FUSION (Phase 7)
  ├─ Deduplicate by chunk_id
  ├─ Apply RRF: 1/(k+rank) where k=60
  └─ Return top 10 (5ms)
  ↓
DOMAIN-AWARE FILTERING (Phase 10) [optional]
  ├─ Domain confidence 0.95 > 0.4 → HIGH
  └─ Prioritize IP domain chunks
  ↓
RERANKING (Phase 12) [optional]
  ├─ Lexical boosting: ++ for "Section 3(d)" matches
  └─ Domain ranking: ++ for IP domain chunks (8ms)
  ↓
FINAL EVIDENCE (K=10)
  └─ Ranked 1-10, score 0.0-1.0
